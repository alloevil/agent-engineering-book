# 第 1 章：Agent 是什么

## 1.1 一个思想实验

假设你有一个永不疲倦的实习生。你对他说："帮我整理一下上周的会议纪要，把待办事项提取出来，分配给对应的人。"

这个实习生会做什么？

- 他会去找到所有上周的会议记录（**感知**）
- 理解每条记录的内容，判断哪些是待办事项（**推理**）
- 把待办事项整理成格式化的清单，分配给对应的人（**行动**）
- 做完后告诉你"已完成，共提取了 12 条待办，分配给了 6 个人"（**反馈**）

如果某条待办事项的负责人不在，他会自己判断是跳过还是找你确认（**决策**）。

这就是 Agent。

现在换个场景。你对 Siri 说："帮我整理一下上周的会议纪要。" Siri 会做什么？

它会搜索"会议纪要"这个关键词，然后——要么找不到，要么给你列出一堆文件名。它不会主动去读文件、理解内容、提取待办、分配任务。

这就是 Chatbot。

**核心区别不是"聪明程度"，是"能不能行动"。**

## 1.2 Agent 的正式定义

一个 Agent 必须具备五个要素：

```
目标 (Goal)
  ↓
感知 (Perception) → 推理 (Reasoning) → 行动 (Action)
  ↑                    ↓
  ← 反馈 (Feedback) ←
```

1. **目标**：Agent 要达成什么。可以是用户给的（"整理会议纪要"），也可以是系统设定的（"每天 9 点推送新闻"）。
2. **感知**：Agent 能获取什么信息。文件内容、API 返回值、用户消息、传感器数据。
3. **推理**：Agent 如何理解和决策。LLM 是当前最强大的推理引擎。
4. **行动**：Agent 能做什么。调用 API、写文件、发消息、执行代码。
5. **反馈**：行动的结果如何影响下一轮推理。成功了继续，失败了调整。

这五个要素形成一个闭环。**缺少任何一个，就不是 Agent。**

| 缺少什么 | 变成了什么 |
|----------|-----------|
| 没有目标 | 聊天机器人 |
| 没有感知 | 盲人摸象 |
| 没有推理 | 自动化脚本 |
| 没有行动 | 智能顾问 |
| 没有反馈 | 单次函数调用 |

## 1.3 Agent ≠ Chatbot

Chatbot 是被动的：你问一句，它答一句。每一轮对话都是独立的。

Agent 是主动的：你给一个目标，它自己规划怎么达成，遇到问题自己调整。

| 维度 | Chatbot | Agent |
|------|---------|-------|
| 交互模式 | 一问一答 | 目标驱动 |
| 状态 | 无状态或弱状态 | 有持续状态 |
| 行动 | 只能生成文本 | 可以调用工具、执行操作 |
| 自主性 | 无 | 有（在约束范围内） |
| 典型场景 | 客服问答、翻译 | 自动化工作流、代码生成、数据分析 |

一个判断标准：**如果你停止输入，它还能继续工作吗？** Chatbot 不能，Agent 可以。

## 1.4 Agent ≠ Workflow

Workflow 是预定义的：每个步骤、每条分支都提前写好了。不管输入是什么，执行路径是确定的。

Agent 是动态决策的：它根据当前状态决定下一步做什么。同样的目标，不同的输入可能走完全不同的路径。

```
Workflow:
  IF 条件A → 步骤1 → 步骤2 → 步骤3 → END
  IF 条件B → 步骤4 → 步骤5 → END

Agent:
  目标 → 推理 → 选择行动 → 观察结果 → 推理 → 选择行动 → ... → 目标达成
```

**Workflow 适合可预测的流程，Agent 适合需要判断的场景。**

什么时候用 Workflow？当任务可以被完全分解为固定步骤时。比如"收到邮件 → 解析附件 → 存入数据库"。

什么时候用 Agent？当任务需要理解、判断、适应时。比如"帮我分析这份财报，找出异常指标，写成报告"——每份财报都不一样，你无法预先定义所有可能的异常。

## 1.5 Agent ≠ 脚本

脚本是无推理的：`if-else` 写死了所有分支。遇到脚本没覆盖的情况，就报错或跳过。

Agent 有推理能力：它能处理从未预见的情况。你让它"分析财报"，它看到一份格式完全不同的报表，也能理解并处理。

**脚本是你告诉机器每一步做什么。Agent 是你告诉机器目标是什么，让它自己决定怎么做。**

## 1.6 自动化五级光谱

从脚本到自主 Agent，存在一个连续的光谱：

| 级别 | 名称 | 特征 | 例子 |
|------|------|------|------|
| L1 | 脚本 | 固定步骤，无推理 | Shell 脚本、cron 定时任务 |
| L2 | Workflow | 固定流程，有条件分支 | Zapier、n8n、Airflow |
| L3 | Copilot | 人类主导，AI 辅助 | GitHub Copilot、Cursor |
| L4 | Agent | 目标驱动，AI 主导，人类监督 | Claude Code、Codex CLI |
| L5 | Autonomous Agent | 完全自主，人类仅设定目标 | 尚未成熟，是研究前沿 |

大多数实际应用处于 L2-L4。**不存在"L5 已经到来"——Self-Evolving Agent 仍在研究阶段。**

关键认知：**不是级别越高越好。** L2 的 Workflow 在处理发票报销时比 L4 的 Agent 更可靠。选什么级别取决于任务的可预测性和错误成本。

## 1.7 什么时候该用 Agent

决策矩阵：

| 任务特征 | 推荐级别 | 原因 |
|----------|---------|------|
| 步骤固定，输入输出明确 | L1-L2 | 脚本/Workflow 更可靠 |
| 需要理解自然语言，但流程固定 | L2-L3 | Workflow + LLM 解析 |
| 需要理解 + 判断 + 适应 | L4 | Agent 的核心价值 |
| 需要跨系统协调 | L4 | Agent 的工具调用能力 |
| 错误成本极高 | L2 | Agent 有不确定性 |
| 任务高度重复 | L1-L2 | 脚本更高效 |

**Agent 的真正价值不是"更聪明"，是"能处理模糊性"。** 当你无法预先定义所有可能的输入和分支时，Agent 是唯一选择。

## 本章小结

- Agent 是目标驱动的行动系统，不是更聪明的聊天机器人
- Agent 的五要素：目标、感知、推理、行动、反馈
- 自动化五级光谱：从脚本到自主 Agent，选什么取决于任务特征
- Agent 的价值在于处理模糊性——当脚本和 Workflow 不够用时

## 思考题

1. 你日常工作中有哪些任务处于 L1-L2？哪些需要 L4？
2. 举一个"用 Agent 反而更糟"的场景。为什么？
3. 如果 Agent 的推理出错了，后果比脚本出错更严重吗？为什么？
