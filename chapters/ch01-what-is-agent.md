# 第 1 章：Agent 是什么

## 一个真实的场景

小张是一家公司的技术负责人。每天早上，他要做这样一件事：

1. 打开邮箱，找到昨天所有会议的纪要
2. 逐条阅读，把待办事项标记出来
3. 查一下每个人负责什么模块
4. 把待办事项分配给对应的人
5. 在飞书上逐个通知

这件事每天花他 20 分钟。不算多，但很烦。

有一天，他想：能不能让 AI 帮我做？

他试了三种方案。

**方案一：ChatGPT。** 他把会议纪要粘贴进去，说"帮我提取待办事项"。ChatGPT 做了——但每次只能处理一份纪要，他得自己粘贴 5 份，然后自己合并结果，自己分配，自己发通知。ChatGPT 只是帮他做了一小步，剩下九步还是他自己。

**方案二：写脚本。** 他写了个 Python 脚本，定时读邮箱、用正则提取待办、自动分配、发通知。前三天跑得很好。第四天，有人在会议纪要里写了个新的格式，正则没匹配到，脚本静默跳过了。第五天，有人请假了，脚本不知道，还是把任务分配给了他。第六天，飞书 API 改了个参数，脚本报错了。

**方案三：Agent。** 他接入了一个 Agent 系统，对它说："每天早上帮我处理昨天的会议纪要，提取待办，分配给对应的人，通过飞书通知他们。如果遇到不确定的情况，问我。"

Agent 做了什么？

- 它读了所有会议纪要（感知）
- 它理解了每份纪要的内容，判断哪些是待办事项（推理）
- 它查了团队成员的职责，把待办分配给对应的人（行动）
- 有人请假了，它检测到了，把任务重新分配（反馈 → 推理 → 行动）
- 纪要格式变了，它还是能理解（推理的灵活性）
- 遇到完全不确定的情况，它在飞书上问小张（Human-in-the-Loop）

**这就是 Agent 和前面两种方案的区别。**

ChatGPT 只能做一步，剩下九步要人补。脚本能做十步，但遇到变化就死机。Agent 能做十步，还能应对变化。

## 那 Agent 到底是什么？

你可能已经从上面的故事里感受到了，但我们需要一个更精确的描述。

Agent 不是一个产品名，不是某个框架，不是某个 API。**Agent 是一种系统架构模式。**

一个系统要成为 Agent，需要满足五个条件：

**第一，它有目标。** 小张说的"每天帮我处理会议纪要"就是目标。没有目标的系统只是工具——你不用它，它就静止在那里。

**第二，它能感知。** Agent 能读取环境信息：邮件内容、飞书消息、文件系统、API 返回值。感知是 Agent 获取信息的通道。

**第三，它能推理。** 这是 Agent 和脚本的核心区别。脚本靠 if-else 硬编码逻辑，Agent 靠 LLM 理解和判断。当纪要格式变了，脚本的正则就废了，但 Agent 能"看懂"新格式。

**第四，它能行动。** 光理解不行动不是 Agent，是顾问。Agent 能调用工具、执行操作、改变环境——发消息、写文件、调 API、执行代码。

**第五，它有反馈。** 行动的结果会影响下一轮推理。任务分配成功了，继续下一条；失败了，换个方案；遇到不确定的，问人。

把这五件事连起来：**目标 → 感知 → 推理 → 行动 → 反馈 → 感知 → 推理 → ...** 这个循环一直转，直到目标达成。

这个循环就是 Agent 的核心。没有这个循环，它就不是 Agent。

## 那 Chatbot 不是 Agent 吗？

不是。

很多人觉得 ChatGPT 就是 Agent。不是的。ChatGPT 是一个非常强大的**文本生成器**——你给它输入，它给你输出。但它的输出是文本，不是行动。它不能帮你发飞书消息，不能帮你读邮件，不能帮你执行代码。

你可能会说：ChatGPT 有插件啊，可以调 API 啊。没错，但那是 ChatGPT 外面加了一层东西——那层东西就是 Harness（我们下一章讲）。ChatGPT 本身只是推理引擎，不是 Agent。

一个更直观的判断标准：**如果你停止输入，系统还能继续工作吗？**

ChatGPT 不能。你不说话，它就静止了。

Agent 能。你设了"每天早上 9 点处理会议纪要"，它每天 9 点自动启动，不需要你提醒。

**Chatbot 是被动的——你问一句，它答一句。Agent 是主动的——你给一个目标，它自己想办法完成。**

## 那 Workflow 不是 Agent 吗？

也不是。

Workflow 是预定义的流程：收到邮件 → 解析附件 → 存入数据库。每一步都是提前写好的，每条分支都是提前定义的。

Workflow 遇到没有预定义的情况怎么办？报错或跳过。

Agent 遇到没有预定义的情况怎么办？**它会想办法。** 纪要格式变了它能理解，有人请假了它能调整，飞书 API 报错了它能重试或换个方式。

**Workflow 适合步骤可以完全预先定义的场景。Agent 适合需要判断和适应的场景。**

什么时候用 Workflow？"收到发票 → 验证 → 报销 → 打款"——步骤固定，分支有限，用 Workflow 比 Agent 更可靠。

什么时候用 Agent？"帮我分析这份财报，找出异常指标，写成报告"——每份财报格式不同，异常的定义需要判断，分析角度需要选择。这些你无法预先定义，只能靠 Agent 推理。

**关键区分：如果任务的所有可能分支都能被枚举，用 Workflow。否则用 Agent。**

## 那脚本呢？

脚本是 Agent 的最简形式——一个推理函数被硬编码为 if-else 的 Agent。

```python
# 这是脚本
if "紧急" in email.subject:
    send_alert()
elif "会议" in email.subject:
    create_calendar_event()
# 遇到没匹配的情况？跳过。
```

```python
# 这是 Agent 的推理
# LLM 阅读邮件内容，理解上下文，决定应该做什么
# 不需要预先枚举所有可能的关键词
```

脚本的优势是确定性——同样的输入永远产生同样的输出。Agent 的优势是灵活性——它能处理你没预见的情况。但灵活性是有代价的：Agent 的输出可能不一致，同样的输入两次运行可能产生不同的结果。

**脚本是 Agent 的特例。Agent 是脚本的泛化。**

## 那到底什么时候该用 Agent？

这是一个最重要的问题，因为不是所有场景都需要 Agent。盲目使用 Agent 是过度工程。

问自己三个问题：

**问题一：任务的步骤能完全预先定义吗？**
- 能 → 用脚本或 Workflow，不需要 Agent
- 不能 → 考虑 Agent

**问题二：任务需要理解自然语言吗？**
- 不需要 → 脚本就够了
- 需要 → 考虑 Agent（或 Workflow + LLM 解析）

**问题三：Agent 出错的后果有多严重？**
- 不严重 → 可以放心用 Agent
- 很严重 → 要加严格的人类审批，或者干脆用 Workflow

一个快速决策：

- 步骤固定 + 不需要理解自然语言 → **脚本**（最可靠）
- 步骤固定 + 需要理解自然语言 → **Workflow + LLM 解析**
- 步骤不固定 + 需要判断 + 错误不严重 → **Agent**
- 步骤不固定 + 需要判断 + 错误严重 → **Agent + 严格 Human-in-the-Loop**

**一个常见误区：把所有自动化都升级为 Agent。** 如果你的任务可以用 cron + 脚本可靠地完成，引入 Agent 只会增加不确定性、成本和调试难度。Agent 的价值在于处理**脚本无法处理的模糊性**——当输入不确定、分支不可枚举、需要判断时。

## 自动化五级光谱

从手动到完全自主，存在一个连续的光谱。参考自动驾驶的分级思路：

**L0 — 手动。** 人类完成所有工作。没有自动化。

**L1 — 脚本。** 硬编码逻辑，if-else 写死所有分支。确定性高，灵活性为零。典型例子：cron 定时任务、Shell 脚本。

**L2 — Workflow。** 固定流程 + 条件分支，可以用 LLM 做解析但流程是预定义的。典型例子：Zapier、n8n。

**L3 — Copilot。** 人类主导决策，AI 辅助执行。典型例子：GitHub Copilot、Cursor——AI 建议代码，人类决定是否采纳。

**L4 — Agent。** AI 主导执行，人类监督。Agent 自己规划、执行、调整，人类只在关键节点审批。典型例子：Claude Code。

**L5 — Autonomous Agent。** 完全自主，人类只设定目标。目前处于研究阶段，尚未成熟。

**关键认知：级别越高不等于越好。**

L2 的 Workflow 在处理发票报销时比 L4 的 Agent 更可靠。选什么级别取决于任务的可预测性和错误成本。

## 回到小张的故事

小张最终选了 Agent，因为他的任务满足三个条件：
1. 步骤不能完全预先定义（会议纪要格式会变，团队成员会请假）
2. 需要理解自然语言（纪要是人类写的，格式不固定）
3. 出错后果不严重（分配错了可以改）

如果小张的任务是"每天定时备份数据库"，他不需要 Agent——一个 cron 脚本就够了，更可靠、更便宜、更好调试。

**这就是本章的核心信息：Agent 是强大的工具，但不是万能的。理解它是什么、不是什么，才能正确使用它。**

## 本章小结

- Agent 是有目标的行动系统，不是聊天机器人的升级版
- Agent 的五件事：目标、感知、推理、行动、反馈，形成闭环
- Chatbot 是被动的（你问它答），Agent 是主动的（你给目标它自己做）
- Workflow 是预定义的（所有分支提前写好），Agent 是动态的（遇到变化自己想办法）
- 不是所有场景都需要 Agent——步骤能预先定义的用脚本，需要判断的才用 Agent
- 自动化五级光谱：L0 手动 → L5 自主 Agent，选什么级别取决于可预测性和错误成本

## 思考题

1. 想一个你日常工作中的重复任务。用本章的三个问题判断：应该用脚本、Workflow 还是 Agent？
2. "如果你停止输入，系统还能继续工作吗？"——用这个标准判断以下系统：搜索引擎、智能客服、定时备份脚本、GitHub Copilot。哪些是 Agent？
3. 你见过有人在不需要 Agent 的场景用了 Agent 吗？后果是什么？
